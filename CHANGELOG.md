# Changelog

All notable changes to `cofkit` are recorded here.

Release versions use calendar versioning in `YYYY.M.D` form. The current release on `2026-09-12` is version `2026.9.12`.

## 2026.9.12

### Added
- Zeo++ atomic-radii override and porosity provenance (impact-review claims T4-08 / T3.8, action A21): `cofkit analyze zeopp` gains `--zeopp-radii-file` (and `analyze_zeopp_pore_properties` / `analyze_zeopp_basic_pore_properties` gain `radii_file=`), passed to Zeo++ as `-r` for every baseline and probe-scan invocation; when omitted, Zeo++'s built-in UFF radii table is used. Every `zeopp_report.json` now carries a typed `radii_provenance` block (`ZeoppRadiiProvenance`) recording the effective atomic radii source (`zeopp_builtin_uff` or `custom_radii_file` plus the resolved file path), the zero-radius point-probe baseline radii, and the requested probe-scan radii; the human-readable CLI summary prints `atomic_radii_source:`. The Monte Carlo sampling defaults moved to owning constants `zeopp.DEFAULT_SURFACE_SAMPLES_PER_ATOM` / `DEFAULT_VOLUME_SAMPLES_TOTAL`, referenced by both the library signature and the CLI argparse defaults (values unchanged)
- effective conformer-construction settings are now recorded in durable build outputs (impact-review claims T1-7 / T3.5 / T3.11, action A18): the monomer builder records the embedding budget it was handed (`requested_num_conformers`), the RDKit embedding seed, whether shape-aware selection was requested (and a `conformer_selection_note` explaining why a requested shape selection was not applied), and the cofkit/RDKit versions in `MonomerSpec.metadata`. Batch runs carry typed provenance: `BuiltBatchMonomer.conformer_provenance` / `BatchRunSummary.conformer_settings` (`cofkit.batch_models.MonomerConformerProvenance` / `ConformerConstructionSettings`), serialized as `conformer_provenance` per record in `monomers.jsonl` (requested vs effective budget — the effective value shows the shape-aware ensemble increase to 16 when it fires — actual embedded conformer count, seed, selection mode, embedding fallback status, builder identity) and as `metadata.reactant_conformer_provenance` per structure in `manifest.jsonl`; `summary.md` gains a `## Construction settings (conformer provenance)` section that explains the two-conformer autodetection clamp, the shape-aware ensemble increase, the seed, and where the per-monomer selected-conformer provenance lives, and the batch console/JSON summaries print/serialize the same settings. Single-pair and ring-forming `summary.json` carry a per-monomer `conformers` block (requested CLI budget vs effective vs actual, seed, selection mode, fallback status, versions), and single-pair autodetection blocks record the clamped probe budget (`probe_num_conformers`). No build behavior changed. Ownership consolidations per the single-owner rule: the default RDKit embedding seed is now owned by `chem.rdkit.DEFAULT_RDKIT_RANDOM_SEED` (referenced by `build_rdkit_monomer` / `RDKitMotifBuilder.build_monomer` signatures, `BatchGenerationConfig.rdkit_random_seed`, and the monomer-library autodetect paths), the two-conformer autodetection cap by `monomer_library.AUTODETECT_MAX_CONFORMERS` (referenced by `BatchStructureGenerator._autodetect_num_conformers` and the resolver defaults), and the three build-CLI `--num-conformers` defaults by `cli_build.DEFAULT_CLI_NUM_CONFORMERS`; the deliberately cheaper `batch-all-binary-bridges` (2) and `default-library` (2) budgets stay as documented command-specific overrides


- shape-aware topology compatibility for 4-connecting monomers: monomers are now classified by molecular-graph symmetry into C4/Td-like or D2h-like node-shape families (`cofkit.node_shape`), while supported nets use canonical node-shape labels (`sql` square, `kgm` rectangular, `dia` tetrahedral); batch topology selection and `NetPlanner` compatibility now reject confident shape mismatches with explicit reasons (e.g. a rectangular tetratopic + linker pair is offered `kgm` instead of `sql`), while `unknown` classifications on either side keep the previous connectivity-count-only behavior; decorated `bex` `4+4` generation is now gated on a rectangular classification when shapes are known, and pair summaries record per-reactant node-shape labels (`reactant_node_shapes` on `BatchPairSummary`, `monomer_node_shapes` in candidate `topology_selection` metadata); the filter can be disabled with `BatchGenerationConfig(shape_aware_topology_filter=False)`

## Unreleased

### Added

- experimental in-process soft-relax pass before CIF validation bucketing (`cofkit.soft_relax`): when enabled with `--soft-relax` on `cofkit build single-pair` / `batch-binary-bridge` / `batch-all-binary-bridges` (`BatchGenerationConfig.soft_relax`, off by default), each staged CIF gets a rough clash-repair / strain-relief descent — harmonic bond springs at the initial bond lengths, Urey-Bradley 1-3 restraints, and a ramped cosine soft-repulsion on non-bonded pairs with DREIDING-table radii, mirroring the LAMMPS `pair_style soft` pre-minimization staging but running in-process with no external binary. Safeguards keep the pass from degrading usable structures: 1-3 / 1-4 pairs are excluded from repulsion unless they sit below a clash floor (so torsions and angles are preserved but pathological bonded-neighbor contacts still get repaired), hydrogen uses a smaller repulsion radius than the DREIDING table value (physical pore-facing and stacked C-H contacts are left alone), and H...N/O/F contacts inside a hydrogen-bond window are not repelled. Validation and bucket routing then see the relieved geometry, so graph-intact structures with post-assembly clashes are no longer flagged `hard_invalid` before the LAMMPS pipeline can fix them. Bond image shifts and distances in the `_geom_bond` loop are re-derived from the wrapped coordinates on write, and per-structure diagnostics (`clashes_before/after`, min nonbonded heavy-atom distances, max bond drift) are recorded under `metadata.validation.soft_relax` in `summary.json` / `manifest.jsonl`; pass failures and non-converged passes warn on stderr and keep the unrelaxed structure. This is not a physical relaxation — the ring-forming CLI path and the cell dimensions are untouched

- per-template realized linkage-bond validation: coarse structure validation now checks the realized inter-monomer bond distances in the exported CIF against a per-template acceptable window (`CoarseValidationThresholds.realized_bridge_bond_distance_windows`, currently `boronate_ester_bridge` B-O at `1.25-1.65` angstrom); out-of-window bonds are reported as `realized_bridge_bond_distance` and classified as repairable `needs_optimization` geometry
- `--shape-aware-topology-filter` / `--no-shape-aware-topology-filter` on `cofkit build single-pair`, `cofkit build batch-binary-bridge`, and `cofkit build batch-all-binary-bridges`: turn 4-connecting-monomer node-shape detection off for enumerated topologies and fall back to connectivity-only selection. The Python surfaces expose the same switch as `NetPlanner(shape_aware_topology_filter=...)` and `COFEngineConfig.shape_aware_topology_filter`.
- single-owner convention for tunable numerics, enforced by tests: `AGENTS.md` now records the rule that every tunable numeric lands as a named constant in its semantically owning module (or a field on the owning config dataclass) with a derived / cited / heuristic-pending-calibration provenance comment, and that CLI argparse defaults must reference the owner instead of retyping literals. New guardrail tests pin the wiring: `tests/test_constants_wiring.py` asserts the assembly cell-default owners, and `tests/test_cli_defaults_wiring.py` fails when an `analyze` / `calculate` argparse default drifts from its owning dataclass field

### Changed

- single-layer (monolayer) CIF exports now use one unified c-axis convention on both build paths: ring-forming monolayers export `c = 8.0` angstrom of vacuum-slab padding instead of the previous `3.4` angstrom (which read as an implicit AA pi-stacking repeat), matching the binary-bridge/embedding path; the defaults on `RingFormationConfig.layer_spacing`, `COFEngineConfig.default_ring_layer_spacing`, and `cofkit build ring-forming --layer-spacing` all moved to `8.0`. Compatibility implication: calculation pipelines that treated ring-forming monolayer CIFs as implicitly stacked will now see an isolated slab with vacuum padding instead. The convention is also machine-readable: monolayer exports record `c_axis_semantics: "vacuum_slab"` in the candidate embedding metadata and emit a `# c-axis-semantics: vacuum_slab` comment line in the CIF, while stacked bilayer exports are labeled `periodic_bilayer` instead; a user-set `--layer-spacing` is still labeled `vacuum_slab` because the value remains padding around one layer, not a physical repeat. As a guardrail, `cofkit calculate lammps-optimize` now prints a stderr `warning:` when a final `fix box/relax` stage is enabled on a CIF labeled `vacuum_slab`, since box-relax can collapse the vacuum direction into a fake stacked solid (closes stacking-fix-plan item W1.4)
- LAMMPS optimization defaults are looser: the fixed-cell minimization force tolerance (`--force-tolerance`, used by stage 1 and stage 2 unless separately overridden) is now `1e-4` kcal/mol/angstrom instead of `1e-6`, and the final `fix box/relax` stage now defaults to its own `--box-relax-force-tolerance` of `1e-3` instead of inheriting the previous stage. The old `1e-6` value was a global force 2-norm target that took 146k-200k FIRE iterations to satisfy on few-hundred-atom charged cells, so the default route routinely exhausted the 200000-iteration cap and reported `converged: false`. The acceptance check itself is unchanged (finite global force norm within the effective per-stage tolerance, plus relaxed virial stress within `--pressure-tolerance`); pass an explicit `--box-relax-force-tolerance` to override the new default, or `LammpsOptimizationSettings(box_relax_force_tolerance=None)` to restore inheriting the previous stage
- boronate ester placement geometry now models the five-membered B-O-C-C-O ring: the `boronate_ester_bridge` profile target is the boron-to-catechol-oxygen-centroid distance (~0.80 angstrom, measured on the CoRE-COF baseline rings) instead of a single-bond-like 1.4 angstrom that stretched realized B-O bonds toward ~1.9 angstrom and oversized unit cells, and the template's planarity/torsion priors are now `planar` / `restricted` like the other fused-ring planar linkages
- node-shape detection for 4-connecting monomers is now advisory for explicitly requested topologies, so hand-written COFids that disagree with the classifier build instead of failing. `cofkit build single-pair --cofid '<...>&&sql&&imine'`, explicit `--topology` requests in `single-pair` / `batch-binary-bridge` / `batch-all-binary-bridges`, `BatchGenerationConfig.topology_ids` / `single_node_topology_ids`, and `NetPlanner` `target_topologies` are all attempted as requested; the conflict is reported as a non-blocking stderr `warning:` and recorded as `shape_warnings` in `summary.json` (top-level plus per-result metadata), in per-structure `manifest.jsonl` metadata, on `COFEngine` candidate metadata, and in `NetPlan` metadata. Decorated `bex` requests from a non-rectangular tetratopic pair follow the same rule. Enumerated topologies keep filtering confident shape mismatches unless the filter is disabled; internal enumerations that are passed as `topology_ids` can stay filtered with `BatchGenerationConfig(shape_filter_explicit_topologies=True)`, which is what `COFEngine` does for its default 3D topology list.
- single-owner rework of the imine/azine bridge geometry (audit finding #15): the exported aryl-C/C=N/aryl-N (and C=N-N=C) geometry is now built by a deterministic closed-form constructor at the template linkage profile's new geometry priors (`BridgeGeometryPriors`, 120.0-degree idealized sp2 angles; the azine N-N target 1.408 angstrom moved onto the profile as a documented carried-over heuristic pending calibration) instead of the previous 721-step angular scan whose displacement-dominated objective exported ~131-degree angles regardless of its target. When the placed anchor span matches the prior-consistent `required_bridge_span` the quadrilateral closes exactly (angles at the priors, all bond lengths exact, E-configuration preserved); otherwise a best-effort least-squares closure holds all lengths exact, balances both angle residuals, and records an honest deviation note in the export metadata (notes never claim an exact fit that did not happen). The embedding-time motif-origin retraction is now derived from the same priors (placing the anchor span at the required value) instead of the hand-tuned 0.11/0.08 constants — the derived fractions (~0.164/0.168 imine, ~0.127 azine at typical aryl side lengths) are larger because the retired constants were tuned against a fit that never reached its targets. One-time baseline shift: exported cells shrink by roughly the retraction delta (1.4-3 percent in-plane on the TAPB/TFB, TPE sql, and hydrazine azine fixtures) and exported imine angles move from ~131 to ~120 degrees; coarse-validation classifications are unchanged (no new heavy-atom clashes; the W7 TAPB/TFB stacking regression keeps its >= 2.5 angstrom interlayer contacts), and a fixed-cell DREIDING LAMMPS optimization of the reworked AA export converges
- cross-cutting assembly cell defaults moved to a new owner module `cofkit.constants`: `DEFAULT_MONOLAYER_C_ANGSTROM` (8.0, the vacuum-slab padding unified earlier this release) and `DEFAULT_LATERAL_SPAN_ANGSTROM` (30.0) are now referenced by `EmbeddingConfig`, `COFEngineConfig`, `AssemblyState`, `RingFormationConfig`, and the `build ring-forming --layer-spacing` argparse default, replacing five independent literals. Ring-template bond lengths moved to `cofkit.ring_geometry` (`BOROXINE_BO_BOND_LENGTH`, `TRIAZINE_CN_BOND_LENGTH`), shared by the reaction profiles and the realization-time ring defaults; the angular-residual down-weight is shared as `geometry.ANGULAR_RESIDUAL_DOWN_WEIGHT` (ring geometry and stacking); `_FRACTIONAL_WRAP_TOLERANCE` has a single definition in `topology_symmetry`. No values changed
- `cofkit analyze classify-output` and the `cofkit calculate` subcommands now take their argparse defaults from the owning config dataclasses (`CoarseValidationThresholds`, `GraspaWidomSettings` / `GraspaIsothermSettings` / `GraspaMixtureSettings`, `LammpsOptimizationSettings` / `LammpsMdSettings`, `HybridMdMcSettings`, `EqeqChargeSettings`) instead of retyped literals that could drift from the library defaults; values duplicated inside `cofkit.graspa` itself (12.8-angstrom cutoffs, 1.0e5 overlap criteria, 1e-6 Ewald precision, the kcal/mol-to-kelvin factor) are hoisted to module-level named constants with provenance comments. No default values changed by the rewiring itself (the Widom 300 K default is separately unified to 298 K later in this release — see below)
- single-owner rework of the boronate-ester bridge closure (magic-number plan W2), finishing the pattern set by the imine/azine rework: the realization-time 721-step angular scan — whose displacement-dominated objective (`0.5*|B-B0|^2 + ... + 0.01*(angle-112.4)^2`) let placement error override the angle prior — is replaced by a deterministic closure at the singly-owned profile priors (B-O 1.44 angstrom, O-B-O 112.4 degrees, `linkage_geometry.BORONATE_ESTER_BOND_TARGET_DISTANCE` / `BORONATE_ESTER_OBO_TARGET_ANGLE_DEG`). B rotates around its C-B anchor while both catechol oxygens are placed exactly by circle-circle intersection; a bracketed golden-section on the pure angle residual (with analytic feasible-interval and branch-kink splitting) closes the five-membered ring exactly when feasible and otherwise reports an honest best-effort deviation in the export note. The boronate placement distance is now derived from the same priors (`t*cos(theta/2)` = 0.8017 angstrom) instead of a bare 0.80 literal, and the profile carries `bridge_geometry_priors` like imine/azine. Regression screen on BDBA x HHTP (COF-5 chemistry, hcb): realized O-B-O angles move from 113.8-113.9 to exactly 112.4 degrees at all six ring sites, B-O distances stay 1.44, no new clashes or `hard_invalid` / stretched-boronate classifications, cells grow 0.012 percent, and a fixed-cell DREIDING LAMMPS optimization converges (starting ~89 kcal/mol closer to the minimum than the pre-rework structure). The linkage-geometry grep gate now also forbids the retired scan constants (`range(721)` / `720.0` / the old objective weights) from reappearing
- default bridge target distance unified at 1.5 angstrom (magic-number plan W3.2/W1.5, owner decision): `reactions.DEFAULT_BRIDGE_TARGET_DISTANCE` owns the fallback for templates without their own target, referenced by both `reactions.py` signature defaults and by `EmbeddingConfig.bridge_target_distance`, which moves from 1.4 to the shared 1.5 — a real change on the unprofiled-template embedding path; every built-in linkage profile carries an explicit target, so shipped templates are unaffected
- Widom insertion default temperature moves from 300.0 to 298.0 K (magic-number plan W3.3, owner decision), unifying with the isotherm / mixture / hybrid-MDMC defaults; the CLI-defaults wiring test now pins the unified 298 K
- covalent radii consolidated (magic-number plan W3.1/W1.4): one cited table (`COVALENT_RADII_SINGLE_BOND_ANGSTROM`, Cordero et al., "Covalent radii revisited", Dalton Trans. 2008 — values verified against the paper) owned by `cofkit.chem.detector` and shared by decompose, replacing two uncited duplicate tables. Bond-detection tolerance models stay deliberately context-specific per owner decision and are now named constants with the rationale recorded: build-side multiplicative ×1.3 with a 0.7 fallback radius (monomers with known chemistry) versus decompose-side additive +0.30 (H) / +0.45 (heavy) with a 0.35 distance floor, a 2.05 B–O ceiling, and a 0.75 fallback radius (unknown input structures, where generosity avoids missing bonds)
- soft-relax repulsion radii are declared intentionally independent of the `cofkit.vdw` Bondi assessment radii (magic-number plan W3.4, owner decision, documentation-only): the pass mirrors the LAMMPS `pair_style soft` pre-minimization staging it precedes, so DREIDING-table radii are the correct physics for the repair descent while Bondi radii remain the assessment standard
- stacked bilayer registries now share one unified default interlayer clearance of 3.5 angstrom (magic-number plan D5, owner decision): the undocumented 3.4 / 3.5 / 3.6 per-registry triple — for which no rationale ever existed in code, history, or docs — is replaced by a single heuristic constant `stacking.DEFAULT_INTERLAYER_CLEARANCE_ANGSTROM`, referenced by the `LayerRegistry` default and every built-in registry. One honest heuristic number instead of three pseudo-precise ones; the values remain global for all 2D COFs and chemistry-unaware, now stated as such. Baseline shift for stacked exports: AA bilayer c grows by 0.2 angstrom, slipped shrinks by 0.2, AB is unchanged (all still `c == 2 * (clearance + layer_z_span)` exactly, and the TAPB/TFB AA/AB/slipped smoke build shows no new contacts below the clash cutoff). The azine N-N target (1.408 angstrom) keeps its value and is now documented as an accepted heuristic within the textbook ~1.40-1.45 angstrom range for such bonds, calibration formally deferred (owner decision, same date)
- provenance documentation pass over every remaining admitted-heuristic numeric in the builder (magic-number plan Tier 4, W4.1-W4.3 — zero behavior change): ~120 previously bare literals across `reaction_realization.py` (azine fit / H-reposition / benzothiazole clusters), `decompose*.py` (topology-ranking weights, bond-order windows, score ladders), `validation.py` (`CoarseValidationThresholds`), `engine.py` / `lammps.py` / `graspa.py` / `zeopp.py` / `guest_restart.py` / `hybrid_mdmc.py` (engine configs), and the remaining builder modules (`optimizer.py`, `embedding.py`, `scoring.py`, `soft_relax.py`, `stacking.py`, `batch.py`, `ring_forming.py`, ...) are now named module constants or documented config fields, each carrying a derived / cited / heuristic-pending-calibration label per the new single-owner convention. Notable provenance established along the way: the EQeq charge parameters (lambda 1.2, hydrogen EA -2.0 eV) are the published Wilmer & Snurr 2012 values and the reference implementation's defaults (cited); the hard-coded decorated-bex cell matches the canonical RCSR/Systre `bex.cgd` cell exactly (cited, only the a/b shape is consumed); RDKit's `pruneRmsThresh` 0.2 is the conventional ETKDG value (cited); the guest rotation move size 0.523583 is 30 degrees in radians (derived). The internal-only benzothiazole prototype is labeled frozen/uncalibrated as a block rather than polished. One mechanical rewire beyond comments: `guest_restart.py` fallback lookups now reference their owning dataclass field defaults instead of retyped literals

### Changed

- shape-aware conformer selection is now active in the binary-bridge pipeline (`single-pair`, `batch-binary-bridge`, `batch-all-binary-bridges`, `BatchGenerationConfig.shape_aware_conformer`, all on by default with `--no-shape-aware-conformer` opt-outs) for 3-connecting monomers, following an A/B screen on the default monomer library (same 16-conformer ensemble, energy vs shape selection): flexible tritopic monomers improved (the hexylamide trialdehyde + p-phenylenediamine hcb build went from `warning` with 6 hydrogen clashes / 2.62-angstrom minimum heavy contact / a skewed 38.3-by-37.0-angstrom cell to `valid` / clash-free / 3.16 angstrom / symmetric 60-degree cell; TAPB + terephthalaldehyde gained a symmetric cell), rigid tritopic controls were byte-identical, and the tetrahedral TAM + terephthalaldehyde dia negative control got mildly worse (a hydrogen-clash warning) because no planar conformer exists for a tetrahedral node — so the gate is `SHAPE_SELECTION_MIN_MOTIFS` to `SHAPE_SELECTION_VALIDATED_MAX_MOTIFS` (both owned by `chem.rdkit`, currently 3..3); 4-connecting monomers keep energy selection until planar-tetratopic evidence exists, and ring-forming keeps its 3+-motif gate since it only builds 2D nets. `SHAPE_SELECTION_MIN_CONFORMERS` (16) moved from `build_workflows.ring_forming` to its owner `chem.rdkit` and is re-exported from the old location. `COFEngine` inherits the batch default; custom `smiles_monomer_builder` callables are never passed the new keyword. Monomer records built with shape selection carry `conformer_selection: "motif_shape"` and `selected_conformer_shape_score` in metadata

### Fixed
- gRASPA/RASPA2 result parsing now survives mixed-schema output files with explicit diagnostics instead of silent component loss (impact-review claim T2-13, action A21): the Widom, isotherm, and mixture parsers previously picked one backend layout per file (gRASPA blocks first, RASPA2 only as a fallback when gRASPA matched nothing), so a file combining both layouts — e.g. concatenated backend outputs — silently dropped the RASPA2 components once any gRASPA block matched. Every parser now detects the backend schema(s) from file content (`_detect_output_backend_schemas`, still never filename-based) and parses both layouts: disjoint component coverage merges completely with a recorded `Mixed-schema file ...` warning (per-component provenance via `GraspaWidomComponentResult.source_schema`, `GraspaIsothermPointResult.source_schema`, and `GraspaMixturePointResult.component_source_schemas`); a component reported by both layouts with identical values is deduplicated with a diagnostic; a component with conflicting values raises an explicit "Ambiguous mixed-schema output file" `GraspaParseError` rather than silently picking one backend; and markers of the other layout that produced no parseable blocks are flagged as possibly unrecoverable. Strict requested-component checks are preserved and sharpened: within-schema duplicate component blocks still reach the exact-component check as duplicates, and the Widom exact-match failure now names the missing / unexpected / duplicated components instead of a bare mismatch message; an unrecoverable mixture parse reports per-file per-schema coverage (`gRASPA block sections provide [...]`, `RASPA2 loading rows provide [...]`, `missing [...]`). Ordinary single-backend fixtures parse identically
- event-mode decomposition now carries a full atom ledger, and charge/stereo scope is explicit (impact-review claims T2-11 / T4-04 / T4-05, action A17):
  - every atom of the input CIF is accounted for in a typed `AtomLedger` (new module `cofkit.decompose_ledger`), serialized under `metadata["atom_ledger"]` on the event-mode result (and as a compact `atom_ledger_summary` per hypothesis): input atoms are partitioned into recovered precursor fragments (per-fragment atom indices, element counts, role, and recovered SMILES), guest molecules (one ledger entry per disconnected non-framework component — `guest_molecule_count` is now reported distinctly from `guest_atom_count`, each guest carrying its own atom count, Hill formula, and net formal charge), linkage residue (product-side atoms excluded from precursor recovery, currently boroxine ring oxygens with a recorded policy), and explicitly unaccounted framework fragments (which still invalidate the hypothesis with `FAILED_UNEXPLAINED_FRAMEWORK`, now with their atoms itemized instead of only counted)
  - the ledger records the reaction atom accounting per fragment: condensation byproduct atoms restored during precursor repair (e.g. one O per imine aldehyde endpoint, two hydroxyl O per boronic-acid endpoint against three residue ring oxygens per boroxine ring) as `reaction_additions`, and product-state explicit hydrogens re-expressed as implicit hydrogens as `reaction_deletions`; a per-element balance check (`input + reaction_additions = recovered_precursor_explicit_atoms + reaction_deletions + residue + guests + unaccounted`) is verified on every reconstruction, with recovered-precursor implicit-hydrogen and total-atom counts reported informationally
  - formal-charge scope is defined conservatively and audited: `_build_bonded_mol` already applies a CIF `_atom_site_pdbx_formal_charge` column to the graph, and the ledger's `charge_scope` block verifies per-fragment that input charges survive into the recovered precursor SMILES (which carry formal charge into the COFid) — status `preserved` when they do, `guest_localized` when charge exists only on reported guest molecules, `restored_by_heuristic` when the valence-driven tetravalent-nitrogen rule created charge the input did not declare, and the explicit unsupported marker `limited` (with the affected fragments and a non-zero `net_charge_delta`) whenever charge was altered, lost, or sits on residue/unaccounted atoms. Net-charge conservation across precursors + guests + residue + unaccounted is checked as `charge_conserved`
  - stereochemistry scope is declared, not silently dropped: decomposition and COFid canonicalization use `isomericSmiles=False`, so stereo is never preserved; input stereo evidence is now perceived from the 3D coordinates (`input_identity_evidence` in build metadata; tetrahedral atom chirality via `AssignStereochemistryFrom3D` — bond E/Z perception is unavailable in this RDKit line) and the ledger's `stereo_scope` reports `unsupported` with the evidence counts whenever stereo was detected, `not_detected` otherwise, and `undetermined` if perception could not run. Atom-resolved formal-charge export into atomistic CIF charge columns and ionic/stereochemical assembly remain out of scope
- event-mode decomposition search is now canonical with respect to input ordering, and tautomer accounting is explicit (impact-review claims T1-12 / T2-7 / T3.9, action A16):
  - hypothesis enumeration no longer depends on input atom/label order: event and site identifiers embed RDKit atom/bond indices assigned in CIF row order, so sorting by them made the subset of hypotheses explored under the per-family cap (256) — and therefore the verdict of a truncated search — depend on how the input file happened to be ordered. `_family_event_sets` now orders site groups and per-site variants by a graph-invariant key built from RDKit canonical atom symmetry classes (`breakTies=False`), and the ring-event greedy overlap acceptance iterates candidate rings in the same canonical order; tied hypotheses are resolved by canonical enumeration order instead of identifier strings. Shuffling the atom-site and bond-loop rows of a CIF now leaves the decomposition verdict, hypothesis semantics, and truncated-search coverage identical
  - chemically distinct alternatives whose element graphs match are no longer labeled exact identity: when recovered fragments share molecular formula, element graph, role, connectivity, and net charge but differ in bond order/H placement (tautomeric or CIF bond-order-noise variants), the aggregation already collapsed them onto a deterministic buildable representative; the result now reports `precursor_identity.status: "element_graph_ambiguous"` (new typed constants `IDENTITY_STATUS_EXACT` / `IDENTITY_STATUS_ELEMENT_GRAPH_AMBIGUOUS`) with every input form and its fragment count preserved under `precursor_identity.alternatives`, instead of letting the selected form read as an exact chemical identity. Unmerged recoveries report `precursor_identity.status: "exact"`
  - alternatives and counts are preserved at selection: results carry `hypothesis_status_counts` (considered hypotheses per event status), `successful_alternatives` (every distinct complete decomposition with family, topology, COFid, and score — the ambiguity set, not just the first eight hypothesis ids), and, on success, `supporting_hypothesis_count` (how many complete hypotheses converged on the selected COFid before deduplication)
  - broader-search assessment: raising the cap from 256 to 4096 changed no verdict across the repository decomposition fixtures, generated imine/vinylene round trips, and a 25-structure CoRE-COF sample (largest theoretical hypothesis count observed: 72), so the default cap keeps its value and owner (`decompose_events._MAX_FAMILY_HYPOTHESES`)
- failure and yield reporting is now complete and reconciles with the durable records (impact-review claims T2-2 / T2-4 / T2-5 / T2-6 / T2-12 / T2-15, action A12):
  - batch yield counts are split explicitly: `BatchRunSummary` gains derived `constructed_structures` (status `ok`; construction success only, not a validation verdict — the legacy `successful_structures` field keeps its value and meaning as an alias), `exported_structures` (alias of `cifs_written`), `screened_structures` (structures with a validation record), and `unvalidated_structures` (validation coverage unmeasured) properties; `summary.md`, the console batch summary, and the CLI JSON summary now print the separated counts alongside the legacy keys, and the JSON summary gains `validation_counts` and `monomer_records_path`.
